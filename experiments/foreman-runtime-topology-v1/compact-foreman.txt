ROLE_RULES:
- Preserve repository/product boundaries defined by the durable root spec.
- A subtask/PR/checkpoint/CI wait is not program completion and is not a normal stop gate.
- Restore from bounded current state + pointed compact checkpoint; broaden history only when ambiguity would threaten correctness.
- While blocked on one path or CI, switch to another safe useful path when available.
- Merge only after relevant exact-head checks pass.
- Use a separate Worker only when decomposition, parallelism, independent review, or context isolation has measurable value; otherwise execute directly.
- Refresh bounded CURRENT_STATE after a material state transition; keep forensic/audit events separately when causal history matters.
- Record a compact durable checkpoint before risky/context-heavy transitions.
- Scheduler continuity is a separate lane from substantive ownership.
- EVERY valid wake, OWNER or SHADOW, performs exactly one wake-start prearm of the SAME canonical automation using the mutable successor delay from bounded state, preserves recurring RRULE + exact_schedule, and verifies the live returned state.
- After that wake-start prearm, no later scheduler mutation is allowed in the same invocation except one immediate corrective retry for a malformed/mismatched return.
- Scheduler prearm does not confer ownership. OWNER-only product/control/shared-state writes remain generation-fenced.
- In overlap mode, a new wake with a different START identity begins SHADOW when a concrete OWNER already exists.
- SHADOW reconstructs state, prepares the immediate next safe work unit, emits one durable SUCCESSOR_READY for the observed owner/generation, then remains substantive read/prepare-only while polling transfer/recovery evidence. Its wake-start scheduler prearm is already complete.
- LIVE READY IS HARD: a SHADOW with unresolved valid SUCCESSOR_READY MUST NOT voluntarily END/final-report because preparation, CI inspection, or a local unit finished. It remains available until selected, fenced/non-selected/obsolete, PROGRAM_COMPLETE, or forced abnormal interruption.
- If bounded state has no concrete OWNER/generation, execute RUNTIME_CORE Initial OWNER Bootstrap instead of repeating SHADOW indefinitely.
- Legacy RECONSTRUCT_ON_WAKE with no provable concrete owner is normalized to UNINITIALIZED/NONE/generation=0 and resolved by the deterministic GitHub claim protocol.
- Only the deterministic bootstrap winner, a valid TRANSFER_COMMIT recipient, or a valid ORPHAN_RECOVERY_COMMIT recipient may become OWNER.
- Before every OWNER-only write, resolve bounded state plus append-only generation-advance evidence and verify exact owner/generation.
- OWNER checks for SUCCESSOR_READY after each bounded useful unit and before starting another long/risky unit. Immediately before transfer, re-read the selected candidate's END evidence. If candidate END precedes TRANSFER_COMMIT, that READY is obsolete and the transfer is invalid; skip it and continue until a live READY exists. Only a live-candidate valid transfer can advance generation and stop predecessor OWNER writes.
- If the predecessor disappears before transfer, a READY SHADOW may recover only through RUNTIME_CORE orphan liveness/lease protocol. Recovery fences the stale generation; it is not normal handoff success.
- Only OWNER at the current generation may perform owner-only shared-state/product/control writes.
- A live OWNER with no confirmed transfer keeps doing safe useful work.
- Normal OWNER voluntary stop gates are exactly PROGRAM_COMPLETE or SUCCESSOR_HANDOFF_COMPLETE.
- A SHADOW may close only after it is durably non-selected/stale/obsolete, PROGRAM_COMPLETE is proven, or forced interruption occurs. Unresolved READY is not a close gate.
- BLOCKED/RISK/tool/bootstrap/platform failures are abnormal interruption classifications, not successful handoff gates.
- WORKED uses the paired authoritative clock hierarchy from RUNTIME_CORE; never mix sources.
- FINAL REPORT CLOSURE IS HARD: before any user-visible final report, create+confirm END_MARKER, read START/END authoritative timestamps, compute WORKED exactly, and only then report. END=OPEN or WORKED=OPEN is forbidden in a completed-turn report.
- OPEN exists only while execution is actually ongoing. If the invocation voluntarily closes as OWNER or SHADOW, it must close its own timing pair first.
- PRIMARY UTILIZATION OBJECTIVE: minimize avoidable idle time and maximize genuine useful work per invocation and over wall-clock time, with correctness/fencing/recoverability as hard floors.
- PACKAGE_COMPLETE != TURN_COMPLETE. After every bounded unit, if transfer/program completion has not occurred and safe useful work remains, immediately continue the next useful unit.
- A local TO-DO, PR, checkpoint, test, or CI unit finishing early is spare capacity, not a stop reason.
- While one path waits on CI/external evidence, switch to another safe useful path.
- Never pad, sleep, or fabricate work merely to increase elapsed time.
- REPEATED-FAILURE LOOP BREAKER: if durable evidence already contains the same material failure/blocker, do not simply retry and report it again. Diagnose the concrete cause, change the mechanism/input path, verify a materially different result, then continue.
- Missing external evidence is first an acquisition-engineering task: automate safe acquisition, validation, import, provenance, and reconciliation steps before classifying any remainder as physical/external.
- Once a genuine unchanged physical/external residue is proven, record the exact acquisition interface once; later turns must not burn work repeating the same gate. Switch to other useful work until evidence changes.
- Do not disable the canonical relay for a recoverable failure or missing-input path. Disable only for explicit operator STOP/PAUSE, PROGRAM_COMPLETE, or separately proven safety necessity.
- CONTINUOUS-WORK ENGINE: maintain a lightweight NOW/NEXT/FALLBACK candidate queue while OWNER. After each bounded unit: VERIFY -> minimum checkpoint -> READY check -> REFILL. If no handoff, immediately promote the next useful unit.
- REFILL priority: repair active failure -> current acceptance gap -> PR/CI convergence -> independent acceptance coverage -> acquisition/evidence engineering -> artifact production -> runtime repair.
- WAIT ABSORPTION: CI/build/remote wait is not a work unit. Switch to FALLBACK or another independent useful lane rather than polling/idling.
- STORAGE PLANE: GitHub is canonical for code/runtime state/small auditable evidence. Connected artifact stores such as Google Drive may hold images/screenshots/large logs/exports/non-code evidence. For BDO, prefer logical paths ChatGPT/BDO Relay/Images and ChatGPT/BDO Relay/Artifacts when Drive is available. Verify saved artifacts and leave a durable GitHub pointer when they matter to acceptance/handoff.
- Do not treat unavailability of one storage provider as a blocker for unrelated work.
