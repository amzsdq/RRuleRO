WORK_DURATION_INVARIANT:
- Source of Truth is GitHub server timestamp, never model output.
- WORKED = END_MARKER.created_at - START_MARKER.created_at.
- Model-written time strings MUST NOT be used for work-duration judgment.

START:
- Restore bounded target/scheduler/ownership/marker state before substantive payload.
- Create GitHub [WORK_MARKER] phase=START; require success and capture comment id + server created_at.
- Do not start substantive payload before START marker success.
- Anchor schedule math to START_MARKER.created_at or OWNER_ACTIVATED_AT as required by scheduler mode.

USEFUL_WORK:
- Continue real useful payload until target. Unit/PR/checkpoint completion or CI wait is NOT terminal.
- No sleep, padding, synthetic work, or bookkeeping invented only to consume duration.
- If one path waits/blocks, choose another safe non-conflicting useful unit.

TERMINAL_GATE:
- Create a server-timestamped CHECK marker before normal CONTINUE final/handoff.
- If CHECK.created_at - START.created_at < TARGET, FINAL/HANDOFF IS FORBIDDEN; continue useful work.
- At actual terminal/handoff create END marker and compute WORKED from GitHub created_at only.
- PROGRAM_COMPLETE, BLOCKED, or RISK may terminate early only when genuinely satisfied.

SCHEDULER:
- SERIAL baseline: NEXT_WAKE = START_MARKER.created_at + TARGET + GAP.
- OVERLAP experiment: SUCCESSOR_WAKE = OWNER_ACTIVATED_AT + OWNER_WORK_TARGET - REQUIRED_HANDOFF_LEAD.
- Scheduler mutation is owner-only. Re-read generation/role immediately before owner-only control writes.
- SHADOW cannot perform owner-only scheduler/control writes.
- After transfer old owner is close/read-only; next cycle anchors to new OWNER_ACTIVATED_AT, not SHADOW_WAKE.

STATE:
- Keep bounded mutable CURRENT_RUNTIME_STATE for hot restore.
- Keep append-only WORK_MARKER/ATTEMPT/RESULT evidence for audit/causal reconstruction.
- Legacy model-written duration is not strict certification evidence.
- Product details and role-specific decisions stay outside Runtime Core.
