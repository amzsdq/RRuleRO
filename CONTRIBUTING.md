# Contributing

Contributions are welcome once the public API and compatibility surface are documented.

Before submitting changes:

1. Do not include credentials, private deployment identifiers, session material, or personal routing data.
2. Keep examples synthetic.
3. Keep pull-request CI read-only and least-privilege.
4. Add tests for behavioral changes.
5. Treat durable identity, leases, idempotency, recovery correctness, and verification as safety properties unless an accepted replacement preserves the same outcome.
